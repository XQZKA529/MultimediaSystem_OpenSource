# media 资源优化记录（2026-10-05）

本轮保持 media 的 SDIO、FAT32、BMP/WAV、目录/播放列表、按键及可靠板间通信功能，优化 FAT32 服务内部的重复硬件。图片缓存仍由 render 持有，显示刷新方式及跨板协议不变。验收使用 TD 原生 DefaultFlow 的普通 GUI Run，并检查最终时序、资源和输入指纹。

## 为什么拆板后 media 仍接近 80%

原单板最终 `MultimediaSystem_v1_Runs/gtz_best/route.qor` 为 9130/9800 Slice（93.16%）；本轮开始时 media 的原生 GUI 最终报告为 7729/9800（78.87%），实际下降 14.29 个百分点。两板各自都使用相同型号 FPGA，拆板不会让保留在 media 的文件系统和媒体解析自动缩小。

拆板新增的 `db_ethernet`、`db_link`、`seam_media` 在优化前的物理层次报告中分别占 758、3344、1390 LE，合计 5492 LE；它们承担 MAC、跨时钟域、可靠重传、会话/顺序/CRC 校验及有界发送队列。LE 是层次面积指标，不能直接当作 Slice 百分比相加。显示、缓存和音频输出的移出，与新增通信硬件同时发生，因而不会得到“单板资源简单减半”的结果。

保留的 FAT32 服务是最大的单模块：优化前物理报告为 4105 LE，综合层次报告为 3191 LUT（不含 ripple）/2443 seq。源文件和最终报告先保存在 `Runs/resource_optimization/baseline/`，用于同口径比较。

## 实现

- FAT32 目录、文件及映射请求串行执行，共用工作簇号、剩余长度、跳数及下一跳计数。待处理映射仍有独立的 `map_pend_cluster/map_pend_size`，只在服务空闲时移交工作上下文。
- 共用簇号减法、簇偏移移位器及偏移寄存器；挂载几何和文件跳数计算共用右移数据通路。
- 合法 FAT32 簇大小为 1、2、4、8、16、32、64、128 扇区，移位量用 3 位表示；非法值由独立标志拒绝，保留原来的错误码。
- 顺序到达的 32 字节目录记录改为共享使能的移位捕获。LFN 字符用固定字段选择，SFN 校验只选择 11 个实际字节，避免宽变量索引和重复地址译码。
- SFN 位置计数收紧到 4 位，旋转校验显式使用位拼接。

保留 Brent 循环检测、跳数上限、超时、取消、非抢占 SD 突发及目录错误处理；没有通过删除功能、扩大 BRAM 使用或放宽时钟/时序约束换面积。仅修改 media 本地 FAT32 RTL；单板基线和 render RTL 保持原有版本。

## 综合筛选

| 版本 | 总 LUT | 总寄存器 | BRAM9K |
| --- | ---: | ---: | ---: |
| 优化前原生 GUI 综合 | 10875 | 9158 | 50 |
| A：目录选择和移位位宽 | 10751 | 9158 | 50 |
| B：共享移位器/偏移，收紧 SFN | 10451 | 9122 | 50 |
| C：再共享串行工作上下文 | 10316 | 8977 | 50 |

C 相对优化前减少 559 LUT、181 寄存器。FAT32 综合层次 LUT 从 3191 降到 2579，seq 从 2443 降到 2239，ripple 从 344 降到 294。总 LUT/寄存器变化与单模块变化不同，原因包括综合器跨模块优化和映射；最终 Slice 以 route QoR 为准，不能拿综合阶段的 Slice 数量签核。

另试验 D：进一步共用目录/文件的扇区索引、地址加法与长度减法，并收紧单簇字节位宽。其综合为 10349 LUT/9003 寄存器/50 BRAM，反而比 C 多 33 LUT、26 寄存器。GUI 与命令行的集成 hold 修复均在 `i_played_frames[29]` 和复位缓冲附近触发 PHY-8023/RUN-8102，因此撤回 D，最终保留 C。没有关闭 hold 修复来发布实验版本。

TD 原生 DefaultFlow 的普通 GUI Run 已完成完整综合、布局、布线及 bitgen，达到上表指标；恢复 C 后再次 Reset Syn/Phy 并使用普通 GUI Run，全量复测也通过，资源和时序指标一致。同一 C 输入的命令行 `Runs/phy_area_c` 也通过最终报告和当前输入/bit 指纹门槛。

第二次 GUI 编译的输入快照早于 Read Design，当前源文件与快照一致；原生运行脚本与 TD 自带 DefaultFlow 一致，集成 hold 修复开启。核对结果见 [GUI 输入与流程证明](../evidence/resource-optimized/verification.json)、[最终资源和时序验收](../evidence/resource-optimized/qualification.json) 及 [最终 route 报告副本](../evidence/resource-optimized/final.qor)。GUI 生成的 bit 为 `MultimediaSystem_media_Runs/phy_1/MultimediaSystem_media.bit`，SHA256 为 `f333461750436ad8f29af200aae3923f192d8a297c40af80c0cc77c1aa15dac4`；正式双板发布清单保留同一 C 源码的 `Runs/phy_area_c` 产物，两者分别记录实际 bit 指纹。

本轮实际节省 **168 Slice，约 1.7 个百分点**，并未把 740 个综合 LUT/寄存器单元直接换算成 Slice 节省。单板 9130 Slice 与当前 media 7561 Slice 相比，减少 1569 Slice，显示占用率从 93.16% 降到 77.15%。BRAM 没有减少：其中链路 20 块、媒体发送/页面缓冲 9 块，合计 29 块；其余媒体存储/解析模块共 21 块。拆板增加了通信缓冲，所以仍然存在较高的片上存储占用。

当前产物的 setup 距 100ps 门槛只有 4ps，hold 裕量 3ps。更大幅度的优化需要继续研究文件系统和通信控制/小存储的硬件组织；不得按剩余容量直接承诺能放入特定新功能。单板基线、render、业务时钟、时序约束及跨板协议未因本轮优化而改变。

物理层次报告中，FAT32 从 4105 LE 降到 3596 LE，但 `db_link` 从 3344 LE 变为 3514 LE；该模块业务RTL及配置未改，实际映射和时序收敛仍会因周围逻辑变化而改变。整个设计从 14776 LE 降到 14429 LE。LUT与寄存器的配对、复制/缓冲和布局位置决定最终Slice，所以必须同时核对综合筛选和实际route结果。

若后续重点是腾出BRAM，可以研究打包链路描述符和重传时间戳：本轮物理报告中，8项描述符与8项时间戳分别占5和2块9K RAM，受宽端口实现限制，物理占用大于有效数据量。打包需要重新设计内部读写仲裁、同步读延迟和背压，并验证可靠重传及普通GUI；本轮没有修改该存储结构，也没有把它的潜在节省计入结果。

## 功能验证

扩展 FAT32 及 map walker 测试在优化前原始 RTL和优化后的 RTL上均通过。测试从 SD 扇区数据和对外输出检查行为，覆盖：

- MBR 后续分区槽、非法 BPB、空 MBR。
- LFN 完整文本、损坏 LFN 校验后退回 8.3 名称。
- 全部 8 种簇大小下的实际文件数据/LBA、碎片映射、一个字节的尾段，以及非法簇大小拒绝。
- 文件/映射之后重新进入目录服务，跨完整扇区的删除条目读取下一扇区中的 SFN。
- 文件读取反压期间排队映射请求；文件完整结束后输出独立的映射段。
- 碎片文件、连续段合并、提前 EOC、循环链、最大文件跳数、突发取消。

另外通过 FAT32 IO 超时、LBA 4GB 边界及重试/取消、WAV 控制器与实际位置模式测试。`tb_fat32_map` 已纳入 media 的独立仿真入口及双板回归清单。

当前 media 工程还完成了复制、重命名到带空格目录且排除生成 Runs 的独立验证：原生工程生成、综合、板间链路仿真及扩展 FAT32/map 仿真均通过，复制后的生产输入与已验收 C 输入一致。证据见 [独立工程验证](../../../doc/dual-board/evidence/portability.json)。

实板 SD、千兆 RGMII、HDMI/SDRAM 和长时间运行仍按已有硬件验收清单执行。
