# 双板链路协议 v1.14

此文描述当前 RTL 实现。两板各自携带本文件副本和 `rtl/pkg/board_link.vh`；构建时只读取本板文件。修改接口时先更新协议，再分别更新实现和互通测试。

## 物理和传输约定

- 点对点 Ethernet，板载 RGMII / 厂商 TEMAC，固定 1000 Mb/s、全双工。没有 IP/UDP/ARP 层。
- media MAC：`02:00:00:00:00:01`；render MAC：`02:00:00:00:00:02`；EtherType：`0x88B5`。
- 帧前 14 字节为 Ethernet 头，接着 32 字节协议头及负载；不足 Ethernet 最小长度补零。TEMAC 生成/校验 FCS。FCS 与填充不参与下述协议 CRC。
- **负载长为 0..1024 字节，必须为 4 的整数倍**。当前本地接口以 32 位字握手，不支持任意字节长度的尾包。
- 整数和负载字以高字节先发送。PCM 字为 `{L16,R16}`，左右声道均为有符号 16 位；播放采样率 48 kHz。

## 32 字节头

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | major | 1；接收方拒绝不兼容的主版本 |
| 1 | minor | 14；v1.14 扩展 UI 快照以传送饱和度，两板配套更新 |
| 2 | type | 0=管理，1=业务 |
| 3 | flags | bit0=required，其他位保留 |
| 4..11 | session | 发送方 64 位会话标识 |
| 12..15 | sequence | 业务包分通道的 32 位序号；ACK 使用此字段传累计下一序号 |
| 16..19 | object | 图片 ID、音频 epoch、UI revision 或管理能力信息 |
| 20..23 | offset | 单位由 opcode 定义 |
| 24..25 | length | 负载字节数 |
| 26 | channel | 0=控制/UI/反馈，1=PCM，2=图片 |
| 27 | opcode | 见下表 |
| 28..31 | crc32 | CRC32(头的前28字节 + 声明长度的负载) |

CRC 使用 reflected 多项式 `0xEDB88320`，初值 `0xFFFFFFFF`，最终按位取反。整图 CRC 采用同一算法，只覆盖所有图片打包字的高字节先发送序列。

业务 object 是不透明的32位字段。当前media的image_id/epoch/revision计数器为24位并零扩展，按模2^24回绕；新旧事务由会话、包序号及当前对象共同限定，不能仅按对象数值比较先后。

HELLO 的 object 为 `{role8,24'h000103}`（role=1 media / 2 render），offset=`0x04020205`（图片/PCM/控制窗口=4/2/2，千兆全双工标识）。HELLO 长度为0。每20ms重复HELLO，兼作存活探测；100ms未收到当前会话的有效消息或PHY失去千兆全双工状态，进入断连恢复。`HEARTBEAT=0x02`保留定义，当前发送端使用重复HELLO。

会话标识由角色和本地自由运行计数器时间戳构成；软复位/重连更换时间戳。它用于隔离旧包，**不是认证或加密**，也不保证两次完整断电启动之间的持久唯一性。上电/重新握手、会话变化与重传耗尽恢复须在实板验收中覆盖。

## 窗口、确认和流控

- 固定保留8个1024字节发送槽：图片4、PCM2、控制2。对端每通道按序交付；重复/乱序包不重复执行。序号模 `2^32`，窗口距离远小于半个序号空间。
- 接收端通过本地 ready 保留整包/整突发的信用。队列满时整包丢弃，原来尚未消费的槽保持所有权；发送方以后重传。
- ACK 的 opcode=`0x03`、type=0、length=0，sequence 为该通道下一期待序号。只有业务消费者接完声明的全部负载字，才推进累计 ACK。
- ACK 释放发送保留槽，**不代表已经显示或已经播放**。`IMG_READY`、`IMG_PRESENTED`、`PCM_POSITION`是独立的业务确认。
- 超过5ms无ACK重传，最多3次重传后重建会话。控制优先于PCM，PCM优先于图片；同通道按序发送。
- 本地发送接口：metadata 的 valid/ready 握手后，必须交付恰好 `length/4` 个字，最后一字置 last。valid 在反压时保持数据不变。接收接口遵循相同纪律。
- 不认识的 optional opcode（required=0）排空后忽略；required opcode 排空后反馈 ERROR。扩展 opcode 放在既有通道内；新增通道编号属于另一次协议扩展，当前实现不接收 channel>2。

## 图片事务

| opcode | 方向/通道 | object、offset、负载 |
|---|---|---|
| `0x10 IMG_BEGIN` | media→render，2 | object=image_id，offset=691200，length=0 |
| `0x14 IMG_READY` | render→media，0 | 同一image_id；写请求应答、FIFO复位释放完成后发送 |
| `0x11 IMG_DATA` | media→render，2 | offset=连续字节偏移；负载为32位打包字 |
| `0x12 IMG_END` | media→render，2 | length=4，负载为整图CRC32；仅源文件读取成功后发送 |
| `0x13 IMG_ABORT` | media→render，2 | 取消未提交的同一image_id |
| `0x15 IMG_PRESENTED` | render→media，0 | 该图片完成写入、**交叉淡化动画结束、旧读缓冲交接完成**后发送 |

## 固定小图事务（v1.11）

根目录 `OVERLAY.BMP` 由 media 识别并从普通图片目录排除。media 仅接受 64×64、24-bit、BI_RGB、正高度 BMP，文件大小须为12342字节；像素以 BMP 自下而上顺序读取，转为 RGB565 后每个32位字按 `{pixel_odd,pixel_even}` 打包。render 将每字节偏移为0..8191的数据写入固定64×64缓存，并在地址中翻转行号。

| opcode | 方向/通道 | 内容 |
|---|---|---|
| `0x16 OVL_BEGIN` | media→render，2 | object=overlay_id，offset=2048个32位字，length=0；render在VS帧界隐藏旧小图后才回复READY |
| `0x17 OVL_READY` | render→media，0 | render已完成隐藏并准备接收 |
| `0x18 OVL_DATA` | media→render，2 | 同一overlay_id，offset=连续字节偏移；固定8192字节 |
| `0x19 OVL_END` | media→render，2 | offset=8192，length=4，负载为传输RGB565字流的CRC32 |
| `0x1A OVL_APPLIED` | render→media，0 | CRC、长度正确且新缓存已在VS帧界提交 |
| `0x1B OVL_ABORT` | media→render，2 | 取消未完成的同一overlay_id，小图保持隐藏 |

media 产生的 overlay_id 使用最高位为 1 的 32 位 object（从 `0x80000001` 开始），与主图的 24 位 ID 分离；render 按不透明 object 字段比较，无需更改线协议版本。共享 ERROR 仅终结匹配的活动事务。快速取消/重试可复用尚未确认的隐藏请求；READY 必须等像素域真实帧界确认，取消必须使旧 commit 保持隐藏。

小图发送与主图共用图片通道、可靠分包窗口和media侧4KiB流FIFO，事务互斥；不改变IMG_BEGIN/READY/DATA/END/PRESENTED含义。render使用2块BRAM32K保存单份RGB565缓存。重连或render复位后media重新读取并发送。缺文件、格式错误、SD读错或CRC失败时小图隐藏，主图事务继续。

传输图像固定1280×720 RGB888；media可读取宽高各1–4096的24bpp、BI_RGB、自下而上BMP，并在发送前以最近邻contain等比例缩放、居中补黑。原图尺寸不进入线格式，协议版本不变；四个像素变成三个字：`W0={R0,G0,B0,R1}`、`W1={G1,B1,R2,G2}`、`W2={B2,R3,G3,B3}`。共691200字、2764800字节。沿用缩放结果的底向上流与render写地址垂直翻转；不改变原颜色深度。

render保有两帧SDRAM：字地址 `0x000000..0x0A8BFF` 与 `0x0A8C00..0x1517FF`。收到整图、CRC正确、真实SDRAM写完成后，在VS帧界启动**两路读取 + 全分辨率RGB888交叉淡化**：旧图与新图各占一路读FIFO，α 在30个帧间隔内由0推进到256（约0.5秒），随后完整输出一帧新图，再切为新图单路读取；确认旧图在途读取排空、旧缓存可安全覆盖后，才发送PRESENTED。动画期间两张缓存均不可被写入，也不接收第三张图片。alpha混合公式为 `round((旧图×256 + α×(新图−旧图))/256)`；不引入Gamma。任一路读通路欠载即终止本次动画、保留旧图并回图片错误，**不发送**成功的PRESENTED。部分图、失败图、断线均不能替换最后有效图片。图片传输频率和本地约60Hz扫描刷新独立。

media图片源FIFO为4KB；FAT图像读突发最多4扇区，授权前至少保留528字信用。render写FIFO为4KB，接收1KB图片包前至少保留288字信用。SD/SDRAM进行中的突发不能靠逐字反压暂停。

## 音频事务

| opcode | 方向/通道 | 内容 |
|---|---|---|
| `0x20 PCM_BEGIN` | media→render，0 | object=epoch，offset=起始绝对样本帧；8B负载：总帧数、初始paused标志(bit0) |
| `0x21 PCM_DATA` | media→render，1 | 同一epoch，offset=绝对样本帧索引，负载为`{L16,R16}`字 |
| `0x22 PCM_END` | media→render，0 | 同一epoch，EOF；尾部短预填充可开始播放 |
| `0x23 PCM_PAUSE` | media→render，0 | offset bit0=paused；bit1=保持freeze，通常为0 |
| `0x24 PCM_FREEZE` | media→render，0 | 冻结播放，等待精确位置反馈 |
| `0x25 PCM_POSITION` | render→media，0 | offset=实际已播放位置；4B负载flags：bit0 playing、bit1 paused、bit2 frozen |
| `0x26 PCM_STOP` | media→render，0 | 停止旧流并切换epoch |

media源FIFO2KB，SD音频突发最多1扇区，授权前至少260字信用。按实际播放位置限制所有已排队、在途及已接收的未播PCM，最大预留1536帧；启动每包前保守预留256帧，并扣除两拍信用流水的余量。新epoch同时重基发送与反馈位置。render PCM环8KB（2048对样本），通常预填充1024对。render本地产生连续48kHz音频节拍；欠载、暂停、断连输出静音，实际位置只随真正播放的样本前进，暂停保留已经预取的样本。

反馈每20ms发送，FREEZE位置稳定后立即反馈，并在后续反馈中持续保持frozen=1，直到解除冻结。反馈可以合并，冻结确认不能仅作为一次事件；media每次快进请求只执行一次，等待冻结期间不再排新的PCM包。快进先冻结、获取实际位置，再从该位置+240000帧（5s）读取，曲尾保留1s；短曲或已在尾部则忽略。新epoch清掉旧PCM。暂停状态跨快进保持。断线恢复从最后确认位置续读，可能重复一个反馈周期内的少量音频；本轮不承诺跨板视频/音频时间戳同步。

## UI与诊断

- `0x30 UI_SNAPSHOT`，通道0，object=revision，offset=0，length=296。首字flags：bit0窗口显示、bit1光标启用、bits7..4光标行；第二字为饱和度扩展字，其后288字节按行存放32×9字符，bit7属性、低7位ASCII。
- media在完整页面生成后冻结发送快照；render写非活动文字bank，在VS提交内容和控制位。提交完成前禁止下一次覆盖。断线丢弃部分页面，保留已提交页面；提交正跨VS时保持bank所有权。
- `0x31 STATUS`，通道0，offset低4位为既有诊断码。render本地断连时显示LINK DOWN。
- `0x7F ERROR`，通道0，无负载，object为相关对象，offset为错误信息：未知required操作码直接返回opcode；`0x1001`整图CRC/长度失败；`0x1002`图片超时。
- 播放OSD、Goertzel频谱模型在render内部形成。内部`OSD_M_W`模型位布局不构成板间接口。

## 版本和扩展纪律

改变像素格式、尺寸、字段含义、通道或必须识别的语义，升级major或另行显式协商；增加可忽略的操作码可用optional扩展。当前HELLO能力字段为固定值，不把未来能力协商当成已实现功能。新增媒体源接media本地服务接口；新增绘制算法接render像素流水线。未来视频的缓存分级和带宽应另行设计并实测，不从静态图片扫描刷新率推导视频帧率。

## 设置菜单与亮度扩展（minor=1）

`UI_SNAPSHOT` 仍为 292 字节。flags[11:8] 为亮度等级 1..10（10%..100%），其他既有位不变。零或越界按 10 处理，兼容旧快照。亮度、窗口和光标控制在复制开始时冻结，复制期间变化则重建；断线重握手重发当前等级。

新增 `0x32 BRIGHTNESS_STATUS`：render→media，通道0，object=0、length=0，offset[1:0] 为 0=检测/调节中、1=DDC 写入回读确认、2=全局 RGB 回退。其余位保留为0。状态在变化和新会话时发送，不影响音频位置反馈定义。

render 的独立开漏 DDC 主机使用 7位 I²C 地址0x37、Get/Set VCP0x10；应答必须通过地址、长度、操作码、结果、功能码、类型、范围和 XOR 校验。显示器最大值为16位，百分比目标为 round(max*level/10)。Set 后回读确认；每次通信之间至少50ms，失败100ms后重试，共3次。失败启用全局 RGB 缩放，5秒后重新探测，支持后恢复硬件控制。

当前固定720p视频模式不消费EDID；原加密HDMI核的EDID触发关闭，DDC引脚与该核隔离，防止两主机同时驱动。DDC SCL/SDA均为开漏并采样实际总线状态，支持时钟延展和事务超时释放。无HPD端口，重新接入由周期探测识别。

RGB 回退位于文字菜单、诊断和音频 OSD 的下游，RGB/HS/VS/DE统一延迟两拍；全局增益在帧界更新。DDC可用时RGB增益为100%，避免常态叠加缩放。用户亮度在media运行期间保留，复位为100%；显示器自身的掉电保存行为不作保证。

协议参考：[VESA DDC/CI 1.1](https://glenwing.github.io/docs/VESA-DDCCI-1.1.pdf)。RGB缩放改变发送像素值；无法替代显示器背光调节的物理效果。若已经调低硬件亮度后DDC通信中断，RGB回退会作用于显示器最后保持的硬件亮度之上。

## 图片对比度扩展（minor=2）

`UI_SNAPSHOT` 保持292字节：flags[20:16]为对比度等级0..20（0%..200%，每档10%），bit21为字段存在标记，其他保留位仍为0。标记不存在或等级大于20时按10（100%）处理，避免旧快照的零值意外生成中灰图。新发送端始终置存在标记。旧接收端忽略这些保留位；需同时更新两板才能使用对比度功能。

对比度等级与文字、亮度和窗口控制一同冻结发送。render在完整UI提交后发出视频域配置更新，独立`contrast_adjust`模块暂存最新值，在VS有效脉冲结束的垂直消隐期应用，下一帧有效像素使用同一等级。断线保留已提交等级、丢弃部分快照；重新握手重发media当前值。

对比度仅作用于交叉淡化后的图像像素，位于诊断文字、设置菜单和音频OSD之前，不使用DDC/CI，不改动SDRAM原图。逐RGB通道公式为`clamp(floor(((c-128)*level+1280+5)/10),0,255)`；等级10精确保持原值，0输出中灰，20为两倍对比度。RGB与HS/VS/DE固定延迟三拍，无图禁用处理保持黑底。最终全局亮度仍在所有叠加器之后。

接口仅消费同一时钟域的RGB888像素流和配置，不依赖720p或BMP，可复用到未来视频像素流；视频解码、缓存及带宽不属于本次扩展。等级在media运行期间保留，复位默认100%。

## 键盘事件（v1.3）

`0x33 KEYPAD_EVENT`，render→media，channel=0，object=0，length=0。
`offset[3:0]` 为行优先编号 0–15（1 2 3 A / 4 5 6 B / 7 8 9 C / * 0 # D）；
`offset[5:4]` 为 PRESS=0、RELEASE=1、REPEAT=2、CANCEL=3；`offset[31:6]` 必须为零。
CANCEL 的键号不参与解释。格式错误丢弃。复用控制通道顺序、重传与去重；metadata 握手交付一次事件。
render 的发送优先级为 IMG_READY / IMG_PRESENTED / ERROR、键盘事件、亮度状态、音频周期位置反馈。
断线清空队列和手势，重新连接必须先松键；不重放旧输入。

## Render 本地文字叠加（v1.4）

`UI_SNAPSHOT` 仍为 292 字节、73 个 32-bit 字：flags bit12 表示 `text_osd_page`，仅窗口开启时有效。该位与窗口、光标、亮度、对比度在 media 构建快照时共同冻结，render 在完整接收后更新，在 VS 与菜单银行一起提交。旧快照该保留位为零，显示普通菜单；两板需配对更新。其他保留位保持零。

media 唯一控制进入／返回／关闭，本地页仍保持窗口开启。进入页复用设置文本的既有快照，返回重画设置页。文字、长度、开关、焦点只由 render 持有，不进入网络载荷，不增加操作码。

render 的独立事件路由在普通页面按原 valid/ready 接口交付事件；文字页消费编辑键，只发送 # 与 CANCEL。按键归属变化取消队列并要求松键。进入页须等待 VS 提交及其同步确认；收到离开快照立即停止编辑，# 交付后持续禁止编辑，直到收到非文字页快照，迟到文字页快照不能解除退出等待。网络重连须收到新的完整快照。IIC 故障取消优先于同拍排队确认。

OSD 配置与网络会话无关：退出、切图、音频、media 复位和重握手保留，render 系统复位恢复默认。视频域单独复位后，本地配置邮箱重新发布当前配置。

## 图片事务取消（2026-10-09修复）

media内部FIFO、BMP解包及缩放状态只在总线时钟边沿消费取消命令，避免组合状态译码毛刺异步复位部分流水线。系统rst仍负责异步复位。网络IMG_ABORT、完整720p载荷、CRC及PRESENTED契约不变，协议版本不变。

## 音量控制扩展（v1.5）

`0x34 VOLUME_SET`，media→render，channel=0，length=0，无载荷。
object为32位音量操作版本号（允许回绕，顺序/去重由可靠链路会话和序号负责）；
offset[4:0]为等级0..20（0%..100%，每档5%），offset[5]表示本次触发关窗快捷提示，
offset[31:6]必须为0。非法通道、长度、保留位或等级不改变已接受配置。

media的独立volume_controller唯一持有等级，上电100%。实际等级变化和关窗快捷边界操作更新版本；
菜单边界无变化不发送。seam在包边界优先发送音量，等待期间合并为最新值，已启动metadata保持不变，
期间的新操作另行待发。首次连接、重连及media复位发送当前等级，提示位为0；render会话重置保留等级。
旧接收端不实现此消息，需配套更新两板。UI_SNAPSHOT仍为292字节，字段布局保持v1.4。

render用独立保持邮箱跨域，在VS原子提交等级和提示意图。后台在四阶段握手完成前不可覆写。
视频域独立复位重新发布当前等级，不重放提示；取消会屏蔽提示但不丢弃用户等级。
PCM输出前使用Q15表 round(level*32768/20)，正负对称舍入（半数远离零），两拍立体声valid对齐。
增益每个48kHz样本向目标移动最多69，最坏约10ms收敛，静音不停止样本消费和位置反馈。
频谱分析使用原始PCM。快捷提示约2秒，重复调节续时，菜单/断线/诊断取消；菜单调节和重连不触发。


## 页面与音量快照字段（v1.6）

`UI_SNAPSHOT` 保持292字节。flags[15:13] 为页面低三位，bit25为页面高位：0 文件浏览、1 设置主页、2 亮度、3 对比度、4 音量、5 SD 字幕、6 转场、7 CLOCK、8 轮播间隔。旧页面号在bit25为0时保持兼容。flags[31:27] 为音量0..20；bit12仍为render本地文字编辑页。轮播间隔值通过现有32×9字符区显示，不新增配置字段或opcode。

## SD 字幕事务（最初引入于 v1.7，当前字段为 v1.12）

`0x35 SD_SUBTITLE_SET`：media→render，可靠控制通道0，object=32位字幕revision，offset=0，固定264字节（66字），required=1。

| 载荷字节 | 内容 |
|---|---|
| 0..3 | flags：bits8:0长度0..256；bit9显示；bit10自动；bit11截取；bit12仅第一行；bits31:13零 |
| 4..7 | 关联image_id；手动模式为零 |
| 8..263 | 256字节文本区；长度以内为ASCII0x20..0x7e，长度以外全部零；每个32位字高字节先发送 |

`0x36 SD_SUBTITLE_APPLIED`：render→media，可靠控制通道0，object=同一revision，length=0，offset=0成功、1自动字幕不属于当前显示图片、2格式错误或会话取消。链路ACK只表示整包交付，浏览器加载成功必须收到业务APPLIED=0。revision允许回绕；会话及可靠序号负责隔离旧消息，不按revision整数大小判断新旧。

media冻结完整待发快照，发送时后续变化保持待发；成功提交后才更新手动保存区和显示/自动开关。手动失败保持原配置。断线保留运行内存，重连重新发送当前有效配置；media系统复位恢复显示关、自动关、空文本。

render用一块BRAM32K保存两银行，在VS原子切换文本、长度、模式与图片关联；收到非法消息或取消的会话不修改已提交内容。业务确认经过四阶段跨域握手，已发布银行在握手收尾前不可覆盖。视频域独立复位重新发布系统域最后成功配置。自动字幕在淡化期间或关联image_id与当前显示图片不一致时隐藏；手动字幕继续显示。自动匹配失败以有效空文本配置清除旧字幕。

字幕显示开时取得主屏顶部文字来源优先权，空字幕仍抑制本地文字。显示关时恢复render原Text OSD开关及内容；本地编辑页始终访问原编辑缓存。菜单或诊断期间隐藏主屏字幕。两来源复用现有text_osd_overlay与共享抗锯齿字库，不增加字体或像素流水。

## 应急控制（v1.8）

render 是模式权威，B/C 不经普通 KEY 事件通路。快照采用通道 0 的四个 length=0 控制消息，依次发送，object 均为同一 request revision：

| opcode | 方向 | offset |
|---|---|---|
| 0x37 EMERGENCY_STATE | render→media | 最后完整图片 ID |
| 0x39 EMERGENCY_EPOCH | render→media | 冻结时的普通音频 epoch |
| 0x3A EMERGENCY_POSITION | render→media | 冻结后的实际消费样本位置 |
| 0x3B EMERGENCY_COMMIT | render→media | bits[5:4] 模式；bits[3:0] 快照标志，其余为零 |
| 0x38 EMERGENCY_STATUS | media→render | 8 bit 状态码，length=4，负载为对应音频 epoch |

COMMIT 模式：0=本地已经恢复/断线退出后的恢复请求，1=应急，2=恢复中。
标志 bits[3:0] 为 `{picture_valid,frozen,paused,playing}`；playing 包括暂停时尚未消费完的音轨。
接收端只在同 revision 的四个字段完整按序收到、保留位合法时一次提交；会话复位丢弃部分快照。render 在重连时重放当前请求；新 revision 的模式请求取消旧业务，旧 revision 回复不能解除当前模式。

状态 1=加载，2=应急流建立，3=恢复，4=原曲目标流建立，5=无原曲，6=缺文件，7=格式错误，8=读/等待错误，9=快照丢失，10=恢复错误。状态 2/4 的 epoch 用于本地声音准入；4 还需本地预填和图片读者就绪才解除。模式 0 在恢复业务完成后作为本地解除确认，media 收到后才放开普通输入和轮播。

新 IMG_BEGIN 在本地应急/恢复期间被拒绝并反馈错误 0x1004；已经接受的事务仍按原 READY/DATA/END/PRESENTED 完成并保持真实错误语义。原音频消息布局不变；WAV 重开由 media 的新增起始样本位置接口建立新的 epoch。

## 日期时钟（v1.9）

UI 快照仍为 292 字节，page=7 表示 CLOCK；bit12 仍只标识 Text OSD。日期、草稿、焦点与应用操作由 render 管理，不新增 opcode，不跨板传输日期值。CLOCK 的矩阵方向/确认留在 render，返回/CANCEL 沿用可靠控制通道；进入后须等视频提交确认再启用编辑。

## 转场配置（v1.10）

`UI_SNAPSHOT` 长度和32×9字符区不变。flags[23:22]表示所选配置：0=Fade、1=Smooth Slide、2=Grid Dissolve、3=RANDOM；bit24是字段存在标记。字段缺失时按Fade处理。v1.10中flags[26:25]保留为零；v1.13复用bit25作为页面号高位，bit26仍为零。对比度继续使用bit21和[20:16]。

settings page=1为主页，page=6为转场子菜单，page=7为CLOCK，page=8为轮播间隔。media发送配置，render接收完整快照后更新，并在图片事务被接受时锁存转场模式。轮播间隔在media本地保存，默认5秒、范围5–300秒、每档5秒；重连保留运行内存值，media复位恢复5秒。转场配置在v1.10引入；v1.13版本的快照布局在v1.14中进一步扩展。

## 图片同名音频与轮播曲尾（v1.13）

同名WAV查找由media复用TXT目录扫描与图片文件名缓存，不新增协议消息或音频目录索引。找到的配音通过现有PCM通道播放。media使用render的 `PCM_POSITION` 实际消费位置和当前曲目帧数判断曲尾；读取流结束不代表播放结束。自动轮播打开时曲尾触发下一张图片，关闭时重播同一曲目。没有同名WAV时不改变独立背景音频播放，并由media轮播计时器按本地配置切图。暂停时不判断曲尾；设置菜单打开时暂停轮播计时，音频继续。

RANDOM每次接受一笔普通图片转场时，从render的64项固定表读取一个两位值并递增六位索引，周期回绕；表内只包含三种实际效果，允许相邻重复。首图仍从黑色Fade，且不取表项。Grid使用固定乱序格子延迟，不需要独立随机数发生器或额外BRAM。

## 图片饱和度扩展（minor=14）

`UI_SNAPSHOT` 共296字节：首字为原flags，第二字bit5为存在标记、bits[4:0]为饱和度0..20，其余位为零，随后是原有288字节字符区。存在标记缺失或值超过20时按10处理。新增页面号9为SATURATION；其余页面号保持不变。该版本与v1.13不可混用，必须更新两板。

media在复制快照时冻结全部控制字段；复制期间参数变化则重建，断线重连重新发送当前设置。render仅在完整快照接收之后提交，VS后的垂直消隐期更新图片参数。关闭菜单、切图、断线保留设置；media复位恢复10。

饱和度仅作用于转场混合和对比度后的图片，先于诊断、台标、菜单、字幕、音频OSD、应急及日期时钟。对RGB像素按 `Y=(77R+150G+29B+128)>>8`，各通道 `C'=clamp(floor((10Y+level*(C-Y)+5)/10),0,255)` 计算；level 0为灰度，10精确不改变像素，20为200%。RGB与HS/VS/DE固定延迟四拍。
