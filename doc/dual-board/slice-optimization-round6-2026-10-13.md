# media 字幕元数据存储实验（第六轮，2026-10-13）

本轮测试三个有效板级候选、四次物理实现，另有一个 32 位 BRAM 端口原型在原生模型检查中被排除。**没有新增合格降幅，三个有效候选都未保留。** media 仍为 **9197 Slice（93.85%）**，render 仍为 **8415 Slice（85.87%）**，推荐 bit 保持第三轮合格版本，实板验收状态不变。

功能、协议 v1.7、106 字符字幕容量、图像/音频精度、分辨率、吞吐和缓冲容量保持原要求，不增加跨功能资源共享。只修改候选中的 `media/rtl/ui/sd_subtitle_controller.v` 和 `media/rtl/ui/subtitle_ram.v`，其余完整构建输入与合格基线逐字节相同。

## 实现与生命周期

### 自动查找的簇号和文件大小

原版在匹配到 TXT 条目时，把当前条目的簇号和大小保存到两个 32 位寄存器。候选移入现有字幕 RAM 的空闲地址 2044–2047：两个原生 16 位端口在条目结束时存簇号，下一拍存大小。第二拍读取的是既有 `file_size` 寄存器在下一条目起始更新之前的值，不要求目录输入总线继续保持条目内容。

目录完成后，三个显式准备状态同步读出并恢复公开的 `file_cluster/file_size`，成功自动查找的文件请求从完成后 2 拍变为 5 拍，即多 30 ns；手动请求流程保持原实现。准备状态不消耗原业务看门狗的工作计数。文本/候选/手动/自动/快照区域最高地址为 747，四个元数据地址不减少原字幕存储容量。

目录扫描和快照传输互斥，借用两个端口只发生在扫描后的空闲间隙。仿真断言检查条目结束、延迟大小写入、准备读取时的端口所有权，确认不与字符写入、下一字符读取或快照传输冲突。pending 手动请求、当前图片信息和旧查找 ID 保持各自的寄存器，继续保留原并发/排队语义。

### 冻结快照的图片 ID

图片 ID 存入同一 RAM 的地址 2042/2043，两个端口在原快照派发时钟同时保存高低 16 位，保留全部 32 位接口精度。flags 等待接收时预读两个 RAM 字；第一个有效 flags 字被接收时，将 ID 拼成原来的第二个 32 位字。后续 B 端口字符预读恢复原序列。

没有新增控制状态或发送拍数，断线时停止发送并按原流程重新冻结。仅在没有旧快照传输时允许写这两个地址；RAM 写入与字符读写的互斥由断言和原生模型验证。整板综合少 20 LUT / 24 FF；生产上下文优化后的 FF 减少量不意味着 RTL 丢弃了 ID 高位，32 位高 ID 用例另行通过。

### 快照标志复用已有 TX 寄存器

该独立候选基于图片 ID 入 RAM 的结构，进一步移除独立的冻结 flags 寄存器。原发送寄存器在复制字幕、尚无有效输出字期间保存 flags，随后沿原握手依次发送 flags、ID 和字幕。

它允许 `word_valid=0` 时的 `word_data` 值与原版不同；全部控制/状态输出和 `word_valid=1` 的数据（包括背压期间的有效字）仍逐周期一致。只在无旧传输的快照派发边沿写 TX，保持冻结和背压稳定性。全局综合少 35 FF、却多 24 LUT；物理实现同样没有收益。

## 端口限制与被排除原型

最初试图把 RAM 改成 1024×32、两个端口同拍存两组 32 位元数据。行为模型的生命周期用例通过，但安装版 `EG_PHY_BRAM32K` 原生接口每端口为 16 位，支持的数据宽度是 8/16；32 位参数和连接不适用，原生仿真失败。

该原型未进入物理实现或生产工程。修正后的三个有效候选均保持原 2048×16 组织，新增独立 `subtitle_metadata_ram` 包装同一原语，启用 B 端口写入。原 `subtitle_ram` 定义保留，render 原来的只读 B 端口实例不受影响。这项失败证据一并归档，不能把纯行为模型通过当作器件可用证明。

## 验证与边界

- 三个有效候选各完成行为 RAM / 原生 BRAM 两种模型的字幕生命周期和真实 FAT 字幕回归，共 12 次用例。覆盖手动 APPLIED 提交/失败/超时、自动大小写/全名匹配、缺失/歧义/不支持名称、快速图片切换、保存/恢复/清空、断线重连和 deferred 设置；真实 FAT 用例覆盖 MBR/VFAT、TXT 在 BMP 之前、碎片化有界前缀读取、BMP/WAV-map 目录所有权及 credit、解析和块失败。
- 查找元数据版在普通、网络背压、高位非零簇号/大小三个配置下，与冻结原版的文件请求、21 个快照及完整协议事件序列一致，每个配置 646 行；成功查找后仅文件请求准备多 3 拍。
- 两个快照候选分别完成普通、网络背压、高位簇号/大小、高位图片 ID 四个配置，同样逐项比较 646 行完整事件序列。数据、revision、文件请求、ACK/REJECT 内容一致，公开请求的时钟不变。
- 图片 ID 入 RAM 版用原生模型同拍运行原版和候选，**51500 次全部公开输出逐周期比对通过**。flags 复用版另有 **51500 次控制/状态及有效数据逐周期比对**，无效周期的数据总线差异按 ready/valid 契约处理。
- RAM 端口所有权和保留地址断言通过；物理报告确认未增加 RAM/DSP。两板生产完整源指纹、依赖审计及 `git diff --check` 通过。
- 本轮没有保留生产 RTL 改动，未重跑全套双板系统聚合回归，也没有宣称完成完整图片/音频并行测速或实板验收。受影响字幕通路由上述真实 FAT、协议、双时钟视图和原生 RAM 用例验证。

## 物理结果的含义

迁移寄存器需要 RAM 地址/数据选择和端口控制，不能只按删除的 FF 数量估算 Slice。图片 ID 方案甚至减少了整板综合 LUT，但后端结果仍更高，时序最差路径也出现在其他模块：seed 3 为 FAT `max_cluster → map_first_valid`，seed 5 为 FAT RAM 到 `map_next_valid`；查找元数据版最差为 seam 寄存器到链路 `peer_age` 写使能。没有把这些违例直接归因于元数据 RAM 的读延迟。

目前只能确认这些具体存储/生命周期改写没有合格整板收益，尚不能推断 media 已达到资源下限。后续应优先寻找能明显减少 LUT 及高扇出控制的架构改动，而不是只减少宽寄存器。
