## 职责与独立工程

| 功能 | media | render |
|---|---|---|
| 存储与素材 | SDIO、FAT32、BMP/WAV 解析、目录和播放列表 | 接收明确格式的图像/PCM |
| 图片 | 选择、读取、打包、整图 CRC、有界发送 FIFO、切图请求合并 | SDRAM 双缓冲、校验、帧界提交、交叉淡化动画、HDMI 扫描 |
| 音频 | 用户意图、文件读取、暂停/换曲/快进控制 | 8KB PCM 环、连续 48kHz 节拍、实际播放位置 |
| UI | 按键、浏览器内容及光标语义 | 32×9 字符快照、音频 OSD、Goertzel 频谱 |
| 链路 | 本板 RGMII/TEMAC、会话与重传 | 本板 RGMII/TEMAC、会话与重传 |

两板各自携带全部 RTL/IP/约束/构建脚本。根目录单板工程保留作基线；板级构建不读取其源码。共同协议文档和定义维护本地一致副本。原生入口为 `MultimediaSystem_media.al` / `MultimediaSystem_render.al`，顶层为 `top_media` / `top_render`。

## 已落实的事务与修复

完整字段见 [protocol-v1.md](protocol-v1.md)。固定 MAC、EtherType 0x88B5、最大 1024 字节负载；ACK 只确认包接收，不代表显示或播放完成。

- 图片固定 1280×720 RGB888，共 691200 个打包字。整图 CRC、实际写完成与旧读缓冲交接均满足后回复 PRESENTED。图片本地扫描约 60.606Hz。
- 新图校验并写入完成后，在 VS 帧界启动**两路读取 + 全分辨率交叉淡化**：旧图与新图各占一路 512×32 位异步读 FIFO，统一调度器每次独占执行 256 字突发，优先补充占用较低的 FIFO；α 在 30 个帧间隔内由 0 推进到 256（约 0.5 秒），再完整输出一帧新图后切为新图单路读取，确认旧图在途读取排空后才回复 PRESENTED。动画期间两张缓存均禁写，不接收第三张图片。混合公式 `round((旧图×256 + α×(新图−旧图))/256)`，不引入 Gamma。任一路欠载即终止本次动画、保留旧图并回图片错误，不发送成功的 PRESENTED。
- 加载与动画期间的切图按键合并为一次待执行切换（`next_pending`），执行一次后清除、不累计；浏览器打开时暂不执行，关闭后继续。首图从黑色淡入；轮播保留约 1 秒停留计时，浏览器打开时暂停。
- TEMAC 单播地址配置按 IP 的字节序转换；512 字节 BMP 头探测可在 IMG_READY 之前独立完成，避免启动环形等待。
- PCM 根据 render 实际播放位置限流，最大未播预留 1536 帧。WAV 的 SD 突发最多一个扇区，本地准入预留 260 帧，兼容单声道与立体声。
- 快进先冻结、等待稳定位置确认，再读 +240000 帧，曲尾保留 48000 帧；冻结反馈持续保留 frozen 标志，单次请求只触发一次执行。新 epoch 同时重基反馈和发送位置，暂停状态保留。
- UI 用完整快照在 VS 提交。音频 OSD 保留原图片作为背景。断线保留已提交图片，取消部分事务，音频保持连续静音节拍。

## 验证与构建证据

已通过链路、TEMAC 网表地址过滤、media SD 启动、FAT32、图片提交、PCM 播放和暂停/快进联合回归。联合音频测试检查真实 PCM 样本编码的绝对帧号，并覆盖反馈积压、单声道、暂停中快进和曲尾钳位。专项结果位于本板 `build/evidence/`，仓库联合结果位于 `doc/dual-board/evidence/`。

此前历史签核：media 为 77.15% Slice / 50 BRAM9K / setup +104ps，render 为 60.47% / 53 / +142ps。它们只对应早期输入；报告与 bit 指纹保存在 [release-pair.json](release-pair.json) 及本板 `doc/evidence/`，当前源码的工具签核以对应编译报告为准。

脚本 bitgen 硬门槛沿用 setup WNS≥100ps、setup/hold 无违例、BRAM9K≤56，并核对输入指纹；Slice 超过80%按既有脚本记录提示。GUI 与脚本产物路径区别见板级 README。独立 PRBS 诊断不替代完整业务验收。

当前没有实现视频文件播放、动态格式协商或跨板音视频时间戳同步。后续新增媒体源归 media，绘制/分析归 render；跨板字段变化同步更新协议与互通测试。

## 图片缩放（2026-10-09）

media输入BMP宽高各1–4096，限定24bpp、BI_RGB、自下而上；独立头解析、像素解包、几何计算和最近邻模块自动contain缩放到720p。宽高按最近整数、半数取偶数，最小1；左/上边距向下取整，余量位于右/下。目标像素中心取样，传输仍为底向上RGB888共691200字。

单行960×32位缓存加1024字节FIFO新增5块BRAM9K。图片文件流单次最多1扇区，FIFO空闲至少528字节才能启动；输出采用独立像素信用，网络FIFO保留16字余量。源成功须文件/解包/缩放/末字排出全部完成，错误取消并重试，重连重新探测。提交CRC/写完成/PRESENTED、交叉淡化与WAV链保持原契约。低对比度可以使补边变灰。

模式枚举CONTAIN=0/COVER=1/STRETCH=2，首版只实现0，其他值在启动图片事务前拒绝。`image_scale_nearest`只依赖稳定几何和ready/valid RGB流；未来扩展采样或模式无需改动FAT与线格式。生产目标固定1280×720；行缓存目标宽度为4的倍数。
