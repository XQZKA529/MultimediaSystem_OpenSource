# 720p 全显示字库抗锯齿升级

本轮修改 render 的全部文字绘制路径：普通设置/文件菜单、Text OSD 编辑页和顶部文字、音频时间、ERROR n / WAIT DATA / LINK DOWN。media 传输的 ASCII、网络协议、菜单快照、106 字符上限保持兼容；根目录单板技术基线未改动。

## 字形与像素

旧实现将 5×7 二值字形复制成 2×2 或 3×3 方块。新版从随仓库保存的 DejaVu Sans Mono Bold 轮廓生成实际屏幕像素，先做 8× 超采样，再面积平均，量化为 0、1/3、2/3、1 四档笔画覆盖率。前景/背景逐通道混合采用 `round((前景×a + 背景×(3-a))/3)`，支持普通文字、琥珀属性字、蓝色光标底和灰色时间分隔符。

| 路径 | 原生字模 | 字符步进/布局 |
|---|---|---|
| 普通菜单、文字编辑、顶部文字 | 10×14，每像素 2 bit | 12×16；32×9 菜单、388×148 窗口和边框保持 |
| 音频时间 | 同一 10×14 字形 | 13 字符、12×16，`/` 保留暗色 |
| 诊断提示 | 独立 15×21，每像素 2 bit | 18 像素步进；支持全部数字和两条链路提示 |

完整字库包含 ASCII 32–126 **95** 个字符，包含大小写、数字和全部可打印标点。空格、控制码、越界字模坐标输出零覆盖率。字体文件及许可证在 `tools/dual-board/fonts/`；render 独立复制时许可证在 `render/doc/font-license.txt`。

目标是消除旧字形放大的大块台阶，让正常 720p 观看距离下的轮廓平滑清晰。720p 本身仍有像素网格，四档覆盖率也有量化，放大截图仍能看见单像素；“基本看不出锯齿”的最终观感需以显示器原生 1280×720 实板显示验收，不能由仿真替代。

## 实现与资源控制

原始 ASCII 字模为 `95×140×2 = 26600 bit`，按每个 16-bit 字保存八个覆盖率像素，放入**一块 BRAM32K**。菜单与 Text OSD 在有效帧内互斥，`render_core` 选择对应的字符/局部像素请求，两路共享一份同步 ROM；地址为 `(ASCII-32)×140 + y×10 + x`，读出对应 16-bit 字并选出其中两位覆盖率。这样不再需要 LUT 行字典查询表。HDL 显式实例化 TD 自带的 `EG_PHY_BRAM32K` 并携带全部 128 个 INIT 参数，不依赖 TD 当前工作目录或外部 `.mem` 文件；生成脚本/TTF 不参与 FPGA 构建。

器件实际拥有 16 块 32 Kbit BRAM，之前全部闲置，可与 64 块 BRAM9K 分别使用。依据为 TD 的 `eagle_s20.db` 综合资源报告及[安路 EG4 器件概览](https://anlogic.oss-cn-shanghai.aliyuncs.com/web_doc/%E5%B7%A5%E5%85%B7%E4%B8%8E%E8%B5%84%E6%96%99%E4%B8%8B%E8%BD%BD/%E6%8A%80%E6%9C%AF%E6%96%87%E6%A1%A3/EG4/%E5%99%A8%E4%BB%B6%E6%A6%82%E8%A7%88/DS303_Eagle_FamilyOverview.pdf)。这里 32K 指 32768 bit（4 KiB），不是 32 KB。单独综合 ASCII 字库，原 BRAM9K 行字典方案为 629 LUT，新 BRAM32K 方案为 52 LUT；整板占用以最终报告为准。

普通菜单保留文本 RAM 一拍、字库一拍的水平提前取样；局部坐标随文本字节寄存。行坐标取当前扫描行，修正旧版依赖底部留白才能掩盖的 `y+2` 提前取样。Text OSD 模块保留四拍 RGB/HS/VS/DE 延迟。音频使用有限字符的组合行覆盖率表，保留流水线。整板在 Text OSD 后增加一拍 RGB/HS/VS/DE 同步寄存，将字库覆盖率与调色板选择从下游亮度乘法器的组合路径拆开；整体输出增加一拍，所有有效像素及同步一起延迟。

诊断字模使用**另一块 BRAM32K**，21 种字符采用五位编号，每个字符分配 32 行×16 列的空间，两位覆盖率，实际 15×21 之外填零。平衡的九字符比较树先定位字符编号/格内列，再以 `{编号,行,列高位}` 直接查同步 ROM，最后从 16-bit 字中选择覆盖率并合成颜色，没有 LUT 字典查询。诊断模块延迟由一拍改为两拍，替代 render_core 原有的后级 `video_stream_reg`，整条诊断链仍是相同的两拍；直通、RGB、HS/VS/DE 都保持一致。相较之前的行字典方案，两份字库合计释放四块 BRAM9K，用两块原先闲置的 BRAM32K，同时减小 LUT 与布线压力；未放宽资源/时序门槛或改变视频频率。

## 复现与验证

在仓库根目录执行（Python 需要 Pillow；字体已随仓库保存）：

```powershell
python tools/dual-board/generate-aa-font.py
python tools/dual-board/preview-aa-font.py
python tools/dual-board/audit.py
./render/sim/run.ps1 -Test tb_font_rom
./render/sim/run.ps1 -Test tb_ui_text_overlay
./render/sim/run.ps1 -Test tb_text_osd_overlay
./render/sim/run.ps1 -Test tb_error_overlay
./render/sim/run.ps1 -Test tb_image_contrast
./render/sim/run.ps1 -Test tb_text_osd_pipeline
./tools/dual-board/run-system.ps1 -Test tb_text_osd_menu
./render/build/run.ps1 -Stage all -RunTag aa_font_bram32 -PhysicalEffort high -PlaceSeed 4
```

独立参考文件 `render/sim/aa-font/atlas.hex` 和 `diagnostic.hex` 由软件轮廓栅格化产生，测试不调用 DUT 查字函数。ROM/音频测试穷举 128 个字符码与 16×16 局部坐标，并检查同步读、间隙及灰色分隔符；普通菜单逐像素检查全部可打印 ASCII、属性、光标、边框、双缓冲/帧界和直通；Text OSD 检查所有焦点、预览滚动、0/1/29/30/99/100/105/106 长度、完整横幅及四拍同步；诊断逐像素检查 ERROR 0–9、WAIT DATA、LINK DOWN、无效数字、直通与同步；联合测试使用真实两板菜单/网络/视频提交并共享字体。

原生 720p 对比图（上旧下新）在 [comparison-720p.png](evidence/aa-font/comparison-720p.png)。它是离线像素模型预览，非显示器实拍；[detail-3x.png](evidence/aa-font/detail-3x.png) 只用于查看单像素覆盖率。逐像素仿真覆盖真实 RTL，日志在 render/build/evidence/ 和 doc/dual-board/evidence/。

仿真直接使用 TD 自带的 `EG_PHY_BRAM32K` 模型及 `glbl`，不是自写 RAM 替身。额外从综合数据库导出门级网表，用 `check-aa-font-init.py` 核对两块实际映射的字库 BRAM32K 全部 65536 bit 初始化，检查记录见 [bram-init-check.json](evidence/aa-font/bram-init-check.json)。独立 ASCII 字库综合网表也通过同一套 35648 次像素检查：`./render/sim/run.ps1 -Test tb_font_rom -FontGateNetlist build/aa-font-bram32-2026-10-09/synthesis/font_probe_gate.v`。这些检查验证 RTL 与映射后的字体初始化/像素/延迟，物理 HDMI 显示效果另行验收。

最终仍高于 80% Slice 提示线，剩余1359 Slice。BRAM9K物理剩余13块、按56块预算剩余5块；BRAM32K剩余14块。保持原 QoR 总 RAM≤56 的保守检查（当前51+2=53），同时明确记录两类 BRAM，避免把 BRAM32K 误标成 BRAM9K。Setup 超过100ps门槛21ps，Hold余量3ps；源代码、约束或布局变化后需重新签核。字模与显示六项回归合计6620028次像素检查，另有35648次映射字库检查与两板菜单联合回归，全部通过。

## 实板验收

只升级 render 即可，media 不需要因字体重新烧录。在显示器原生 720p 下查看全部菜单、长/短文件名大小写及标点、编辑页全部控件、106 字符满行、音频时间和各诊断提示；检查边缘灰阶、下伸部、光标底色、退出/重入和亮度调整。保留之前通过实板的 GUI bit，便于比较实际观感及其他功能。
