## 保留组合中的代码改动

- 两板 RX 头按字节组装，直接写未占用槽位，MAC 按字节累计比较；通过地址、长度、CRC/FCS 校验之后才发布。管理字段利用正常头槽的未使用第 7 字存储，随后逐字搬运到管理 FIFO。满正常队列不会阻塞管理报文；既有槽位数和 Gray 指针同步保持不变。
- media FAT 目录项从 256 位移位副本改为已有同步扇区 RAM 上的地址、等待、消费阶段；SFN/LFN 与 metadata 分开读取。挂载原始参数与解码副本按生命周期复用，活动操作与 pending 请求保持独立。FAT 状态编号压缩为 7 位，业务状态顺序和异常优先级保持不变。
- media 合并互斥发送对象的冻结寄存器，单独保留音频 begin 对象的独立生命周期；BMP 54 位位置移位改为带终态的 6 位索引；图像准备期两次乘积共享一个乘法器，增加一拍准备，实时缩放与行缓存节奏保持不变。
- media LBA 文件流在 burst/retry 期间直接保留活动 cur_nsec，移除其 24 位重复快照；内部 burst_nsec 按 MAX_BURST 上限裁剪（默认 64 需要 7 位），外部 blk_count 仍完整 16 位。没有增加事务周期或改变重试/取消/背压次序。
- 两板 TX 头直接引用仍被 MAC 占用的 descriptor RAM，保留 session、sequence、CRC 及管理类型冻结字段。取消会话后保持 RAM 读地址，并由 `mac_busy_clear` 排除新写者，直到旧 MAC 帧结束。只裁剪准入已证明为零的长度和通道高位。
- render Goertzel 两组带符号状态合并为显式同步 BRAM，读写阶段不变；抗锯齿字体重排成 16×16 地址布局，像素值逐项保持；CLOCK 字符格式 ROM 使用已经按帧提交的日期数字。UI 背景和白色覆盖率算术转换为六个独立 ROM，吸收原有两级算术寄存器，保留原像素输出和 HS/VS/DE 延迟。
- render CLOCK 白色覆盖率调色表使用两块双口 BRAM9K，Text OSD 的背景/光标/阴影算术使用一块 BRAM32K 和一块 BRAM9K；均吸收原有输出寄存器，CLOCK 三拍、Text 四拍延迟保持不变。
- render DDC 的 tick/age 计数器按可达上限裁剪，75 MHz / 50 kHz / 20 ms 默认参数下分别为 10/21 位。age 保留 timeout 当拍额外自增到 TIMEOUT+1 的值，绝对超时、SCL 拉伸等待和两级 CDC 同步寄存器保持不变。
